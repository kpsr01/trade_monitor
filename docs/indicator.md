# Indicator specification and verification

## Current simplified strategy

**Selected policy: simplified C2/CISD with daily exit.** The restored C3/C4/T-spot experiment is archived, not the active strategy. The selected 2025 primary-archive gross totals are +14.61R, +50.89R and +10.10R for 1H → 5M, 30M → 3M and 15M → 1M respectively.

The dashboard now calls `evaluateSimpleStrategy` in `src/lib/simple-strategy.ts`. Its current execution model is `src/lib/simple-backtest.ts`: closed HTF sweep, frozen CantoLab CISD level, first later LTF close strictly beyond that level, entry at that close, exact HTF wick stop, and target 2R. The confirming candle must start at or after the HTF sweep closes. Earlier reclaim flags are never adopted. The strict beyond-level predicate does not require a new crossover after the sweep.

All sweeps are independent and can enter once. No C3/C4 expiry, T-spot invalidation, replacement, pre-entry wick rejection, visibility filter, opposite-side filter or overlap filter is applied. With these extra invalidations removed, a pre-entry wick breach does not cancel a later positive-risk close entry. Daily exit is the backtest default: trades exit at SL/TP or actual session end, whichever comes first. Carry remains an explicit research option and exits only at SL/TP. Non-positive risk is rejected. Unknown data paths are not fabricated. The [current report](../reports/backtest-2025-simple/report.html) and its audit describe this model; the original source's full lifecycle below describes the preserved older implementation, not the active dashboard.

The three cards are summaries, and the all-sweeps lists retain every signal in the fetched history. Backtest eligibility never depends on which signal a card displays. Because expiry has been removed, rolling five-day live data can lose still-pending sweeps from older history; the dashboard remains a bounded reconstruction, not a persistent all-history signal store.

## Preserved full-indicator implementation

The [restored full-rule comparison](../reports/backtest-2025-full-rules/report.html) uses this engine with `postSweepOnly: true`. The option blocks every confirmation at or before the HTF sweep close, including adopted early reclaim flags. Its default remains false for reproducibility of earlier source-mode reports. Full-rule entries are fed to the independent-position simulator with their original confirmation availability; it does not apply card visibility or the old position cap. Optional explicit invalidation events exit at the next eligible minute open after resting gap orders. Those hooks are absent from the simplified run, whose saved baseline remains unchanged.

Full-rule report metadata includes the C1 reference, C3/C4 T-spot bounds with availability timestamps, and the confirmation phase. These are retrospective research details and do not feed execution. The indicator has no separate C1 entry, T-spot-touch order, or deviation-projection entry rule. C3 and C4 CISD entries are part of the same C2 setup family. The user's 2R bracket is retained instead of substituting visual deviation levels for targets.

The reference is [CantoLab/open-source-fractal](https://github.com/cantolab/open-source-fractal/blob/1bb53262deba9456f2b1a85d15c6ac5a5e880cf7/openSourceFractal.pine), commit `1bb53262deba9456f2b1a85d15c6ac5a5e880cf7`. The unchanged Pine source, MIT license, commit, and SHA-256 are in `reference/`. The TypeScript implementation is `src/lib/indicator.ts`.

## Deliberate causal differences

An exact visual replay of this Pine script and a non-repainting dashboard cannot be the same thing. The source requests current HTF data with `lookahead_on` (line 476), retroactively draws C2/C3 objects after confirmation (lines 503–522), and deletes C4-only confirmation history after invalidation (lines 616–637). This port does none of those operations.

1. OHLC groups require every minute and a completed close. The source's already-finished C2 predicates are preserved, without reading future HTF values.
2. Early CISD can qualify C2, but the opportunity becomes available no earlier than the C2 close. A previous intraperiod entry is never invented.
3. Entry is the causally available confirming close. Wick and C4 invalidation checks run before assigning that candle's closing-price entry; a setup invalidated earlier in that candle cannot enter at its close. The backtest begins bracket evaluation on subsequent minutes, so the entry candle's earlier high/low never exits a trade before it existed.
4. Invalidated signals remain in event history. The current card becomes Invalidated; past confirmation is never deleted. Event IDs are deterministic per instrument, pair, C2 start, direction, and transition.
5. C2 formation is processed inline at every HTF close, including when no following candle exists. C4 expiry is likewise known at its final close, so a completed setup does not remain actionable overnight.
6. The **final C3 candle's close** is a special source-order boundary: the source advances to C4, computes the T-spot from the next HTF open, checks C4 invalidation, and only then tests that previous close for CISD. The port preserves that classification. In this closed-only application, the first following LTF candle must close before its open/wick is available. A first confirmation on the final C3 close therefore enters at that following candle's close if the setup survives; it is classified as C4. It never receives a fill at the earlier C3 close. The final C4 close cannot start a new CISD because the source finishes the setup before testing that previous close. C2 wick breaches are still checked on every closed C3/C4 candle, including the final one.

The current candle's wick is checked **before** deferred previous-close C4/CISD checks, as in Pine lines 835–842. A first C4 candle that breaches C2 cannot emit a new deferred CISD confirmation, even when the preceding C3 close crossed the level. This was corrected in the deep review; earlier reports' trade fills were unaffected, but their raw event logs can contain these rejected confirmations.

An unusual original rule is preserved: if C4 is flagged invalid **before** its first CISD confirmation, `checkCisdConfirm` does not test that flag, and a later CISD can still confirm. `checkC4Invalid` then skips subsequent checks because its flag is already set. Conversely, when the first CISD occurs in C4 before that flag, a later T-spot breach kills the setup. Treating all C4 flags as automatic rejection would implement a different strategy.

The signal timestamp is the confirming candle's close (or C2 close for an early CISD). `entryAt`, the entry event's `time`, and its `availableAt` identify the first eligible closed-candle price at which the complete setup is causally known. These normally match the signal timestamp; the late C3 boundary described above can produce a later entry. The confirmed event's `price` remains the CISD trigger level, while the entry event's `price` is the actual eligible close. Availability is market time, not the wall-clock time Yahoo delivered it. Add provider delay and up to another 60 seconds for polling. Prices are historical references, not immediately executable quotes.

Yahoo's public index feed is treated as delayed with no guaranteed fixed delay. The server uses provider quote time to reject a latest candle that is still forming in provider time, even when wall-clock time is later. The engine's `now` is the last accepted minute's close. `updatedAt` consequently means evaluated-through market time; HTTP fetch time is shown separately. Index stops and 2R targets do not imply the same risk/reward in an option contract. Options prices are viewed externally on NSE and are not inputs to this engine.

The bullish stop is the exact C2 low; the bearish stop is the exact C2 high. There is no buffer or tick rounding. Risk must be positive; the target is `entry + 2 * (entry - stop)` for a bullish trade, or `entry - 2 * (stop - entry)` for a bearish trade. An exact stop touch executes in the backtest, although the source's setup invalidation requires a strict wick breach. The live application displays levels without tracking positions or execution. The separate historical backtest applies the explicitly documented fill, cost, gap, and overnight-carry assumptions in its report.

The current backtest has no forced session exit. An entered position survives C3/C4 expiry, replacement, and day boundaries; only its bracket or an explicit invalidation closes it. This position state is separate from the live card's setup lifecycle. Normal overnight/weekend/verified-holiday gaps carry to the next eligible opening price. Missing execution minutes leave the trade unresolved and block subsequent entries for the rest of that replay. A valid position at the data horizon remains open. The report explains the regular-session execution window and the separate clean-data study; the original Pine remains unchanged.

## Sessions, gaps, and state

The initial implementation supports NSE cash-session data, 09:15–15:30 Asia/Kolkata. Intraday groups anchor at 09:15; the last hourly candle is a 15-minute group, closed at 15:30. Holidays are determined by supplied data, not a hardcoded holiday calendar. Out-of-session rows are ignored. Do not use these session settings unchanged for other exchanges, overnight products, or special trading sessions.

The year-study engine now accepts verified `sessionOverrides` with actual opening/closing minutes per IST date. These affect aggregation anchors, shortened final candles, adjacent-session continuity, carry gap checks and forced daily exits together. The 2025 study includes February 1 Saturday trading and October 21's 13:45–14:45 Muhurat session. Normal dashboard defaults remain 09:15–15:30; special schedules must be supplied explicitly. The backtest uses an explicit holiday calendar and does not infer an unexplained missing weekday to be a holiday.

Incomplete aggregates are omitted. A resulting intraday gap resets levels and setups, preventing false adjacency across missing bars. That reset's `availableAt` is the first accepted post-gap LTF candle's close, not its open: the engine consumes closed candles only. A gap from an actual session close to the next available session open is expected and retains state. Conflicting duplicate timestamps and malformed OHLC are rejected. Identical duplicate rows are deduplicated.

Each combination runs from its own local state; no variables are shared between 60→5, 30→3, and 15→1. Both bullish and bearish source states are retained. The card chooses the newest active setup; an exact same-time directional tie is displayed as Forming with an ambiguity message. The recent event list retains both sides. Only the latest 60 transitions per pair are returned. Replay is bounded by the server's historical lookback: the first complete HTF is warm-up, and a fixed CISD level inherited from before the fetched history is unknowable. This is a finite-history limitation, not proof of all-history equivalence.

The year replay captures entry visibility after every mutation at that candle's close, using the same setup-selection function as the dashboard. This avoids reevaluating the full history for every entry. Tests compare these captured decisions against separately evaluated prefixes, and compare complete ledgers/events to the frozen earlier implementation. Candle aggregation streams sorted groups while still requiring every constituent minute; it does not fill gaps.

## Tests and what they establish

Run `npm test`. `tests/indicator.test.ts` includes hand-derived source-rule fixtures for bullish/bearish sweeps, run-open CISD, dojis, strict comparisons, the ten-bar search bound, C2/C3/C4 lifecycle, early-versus-late C4 invalidation, simultaneous directions, confirmation-close entry, exact stops, incomplete candles, missing data, overnight continuity, deterministic event IDs, and prefix invariance. Backtest tests verify exit timing after the entry close, stop-first ambiguity, gaps, and invalidation exits. The tests also check the pinned source's SHA-256 and its original C2 predicates.

These tests validate the port against expected results derived from the checked-in Pine source. **They do not execute TradingView's Pine runtime and are not an independent market-data parity certification.** To perform that check, load the pinned script on the matching TradingView LTF, set its matching fractal and Neutral bias, export identical OHLC and timestamps, and compare C2 extrema, fixed CISD level, confirming closes, and C4 invalidations. Compare causal event times, not retroactively drawn label locations; account for the timing differences above and TradingView/Yahoo feed differences. Upstream candle corrections and the rolling five-day history window can change a reconstructed result; causal processing does not freeze or certify the provider's history.

For the 2025 comparison, `scripts/audit-year-backtest.mjs` separately aggregates the raw candles, checks every C2 sweep against the original strict predicates, verifies each filled trade's C2 wick and positive-risk 2R calculation, then replays every subsequent minute for opening gaps, bracket ordering, invalidation and session exits. It also reconciles overlap, open year-end positions and summary statistics. It does not import the indicator or simulation implementation. Source-derived tests separately cover run-open selection, dojis, early confirmations, C3/C4 ordering, strict breaches and causal late entries.

The deeper review adds `scripts/lib/pine-reference.mjs`: a separate literal translation of Pine's bullish/bearish level/reclaim series and an independent per-C2 walk of the causal C3/C4 lifecycle. It imports no production engine functions. `node scripts/audit-signal-reference.mjs` compares every frozen level, its originating candle, its reclaimed flag, and the complete event set across both year archives and all three pairs, including setups that never traded. `tests/source-review.test.ts` also compares seeded OHLC paths and explicit warm-up regressions. This is a second implementation of the documented causal interpretation, not execution of the original Pine runtime. The [review report](../reports/deep-review-2026-11-08/report.html) records defects, before/after evidence, and limitations.
